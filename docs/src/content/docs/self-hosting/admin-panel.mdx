title: Admin Panel (Mini App)
description: Enable and operate Alita Robot's optional Telegram Mini App dashboard — environment variables, HTTPS, reverse proxy, entry points and failure modes.
---

The admin panel is an optional Telegram Mini App dashboard served by the bot's
own HTTP server under `/panel`. It is off by default: with `PANEL_ENABLED` unset
or `false`, `/panel` and `/panel/api/v1/*` return 404 and the bot behaves
exactly as before — no dashboard buttons, no menu button change, nothing new to
secure.

There is no second process, database or frontend build to deploy: the panel
lives in the same binary and is served on the same port as `/health`,
`/metrics` and `/webhook`.

## Enable it

1. Pick the public HTTPS host the bot will answer on — the same host as
   `WEBHOOK_DOMAIN` is the usual choice.
2. Point a reverse proxy at the bot's `HTTP_PORT` (default `8080`) and forward
   `/panel` and `/panel/api/*`, plus `/webhook` if you use webhooks.
3. Set the variables below and restart the bot.
4. Send `/start panel_<chat_id>` to the bot in a private chat to check it.

No BotFather setup is needed: `web_app` buttons and the menu button open any
HTTPS URL. BotFather's `/setdomain` is for the Telegram Login Widget, which the
panel does not use.

```bash
PANEL_ENABLED=true
PANEL_PUBLIC_URL=https://bot.example.com/panel
```

The bot serves the panel under `/panel` on its own port, and the shell calls
`/panel/api/v1/*` with root-relative URLs. `PANEL_PUBLIC_URL` is the URL
Telegram opens, so it must end with `/panel` unless your proxy rewrites the host
root to the panel.

With the repository's `docker-compose.yml`, only the variables listed under
`services.alita.environment` reach the container: add `PANEL_ENABLED` and
`PANEL_PUBLIC_URL` there (the same goes for any other optional variable).

## Environment variables

| Variable | Required | Default | Meaning |
|----------|----------|---------|---------|
| `PANEL_ENABLED` | No | `false` | Serves the panel and turns on the dashboard buttons. |
| `PANEL_PUBLIC_URL` | When enabled | — | Public HTTPS URL Telegram opens for the panel, for example `https://bot.example.com/panel`. A trailing slash is trimmed. The bot fails to start without it when the panel is enabled. |
| `PANEL_MINIAPP_SHORTNAME` | No | — | BotFather Mini App short name. When set, group buttons open `https://t.me/<bot>/<short_name>?startapp=chat_<chat_id>` directly instead of hopping through the bot's private chat. |
| `PANEL_SESSION_MAX_AGE` | No | `24h` | How old a Mini App `initData` payload may be before the panel rejects it. Go duration syntax (`30m`, `24h`); a value that does not parse fails startup. |

`PANEL_PUBLIC_URL` must be `https://`; `http://` is accepted only when
`DEBUG=true`, because Telegram refuses to open a Mini App from an insecure
origin.

## HTTPS and the reverse proxy

Telegram only opens Mini Apps from an HTTPS origin. The bot itself speaks plain
HTTP on `HTTP_PORT`, so the certificate belongs to whatever sits in front of
it — Caddy, nginx, Traefik, Cloudflare Tunnel, or your platform's load
balancer.

With Caddy in front of the same container:

```caddyfile
bot.example.com {
	reverse_proxy 127.0.0.1:8080
}
```

With nginx:

```nginx
server {
	listen 443 ssl;
	server_name bot.example.com;
	# ssl_certificate / ssl_certificate_key ...

	location /panel {
		proxy_pass http://127.0.0.1:8080;
		proxy_set_header Host $host;
		proxy_set_header X-Forwarded-Proto $scheme;
	}

	location /webhook {
		proxy_pass http://127.0.0.1:8080;
	}
}
```

`PANEL_PUBLIC_URL` is what the buttons open, so it must be the proxied panel
URL (for example `https://bot.example.com/panel`), not `http://localhost:8080`.
Both proxy snippets above pass the path through unchanged, which is what the
panel expects. If the proxy serves the panel on a different host than the
webhook, that is fine — both are just paths on the one server.

## Optional: the direct Mini App link

By default a group button opens the bot's private chat with a
`/start panel_<chat_id>` deep link; the bot then replies with a `web_app`
button that launches the panel. That works with no BotFather setup. Creating a
Mini App in BotFather gives you a short name, so the button can skip the hop:

1. In [@BotFather](https://t.me/BotFather), send `/newapp`, pick the bot and
   follow the prompts — or use `/mybots` → your bot → **Bot Settings** →
   **Configure Mini App** → **Enable Mini App**.
2. Give it a title and the panel URL: the same value as `PANEL_PUBLIC_URL`.
3. Note the short name BotFather shows for the Mini App.
4. Set `PANEL_MINIAPP_SHORTNAME` to that short name and restart.

Group buttons then point straight at
`https://t.me/<bot>/<short_name>?startapp=chat_<chat_id>`, which opens the panel
without a message in between. If the short name is wrong or the Mini App is not
enabled in BotFather, Telegram opens an empty page — remove the variable to fall
back to the deep link.

## Entry points

With the panel enabled the bot adds these, and nothing else changes:

| Where | What |
|-------|------|
| Private chat, menu button | The default menu button becomes a Mini App button labelled "Open admin panel" (in English) that launches `PANEL_PUBLIC_URL`. It is set once per start, so a restart is harmless. |
| Group `/settings` | Below the existing "Open settings in PM" button, a second row opens the panel for that group. |
| Group `/help` | Below the existing help button, a second row opens the panel for that group. |
| Private chat, `/start panel_<chat_id>` | Replies with the same `web_app` button, for links copied by hand. |

With the panel disabled both group keyboards are exactly what they were before:
one button each, no dashboard row, and the menu button is never touched.

## What admins see

The panel authenticates every request with Telegram `initData`; there are no
passwords, cookies or server-side sessions to manage, and the signature is
checked against the bot token on arrival.

- The **chat list** shows the groups where the bot has seen you, ordered by
  last activity and capped at 50. When the panel is opened from a group's
  button or Mini App link, it opens that chat directly. The session itself makes
  no Telegram calls: opening a chat is what verifies your role there.
- Opening a chat shows its details: **your role** (Admin or Read-only) and
  whether the **bot is an admin** there, followed by the dashboard screens
  registered for that chat.
- The **overview** screen is the first entry in the dashboard list: the
  Telegram member count, a 7, 30 or 90 day chart of messages, joins and
  leaves, the window's moderation count and the five most recent moderation
  actions (action, actor, target and time — never message text). Admins see
  the actor and target by the name and @username the bot last saw; members see
  user IDs. Switching the
  window redraws without a page reload, and a chat with no recorded activity
  says so instead of drawing an empty chart.
- **Activity** shows the same window as a heatmap of messages by weekday and
  hour (each cell shaded by its average per day), with the busiest hour, and a
  chart of the Telegram member count. Heatmap hours and weekdays use the chat's
  timezone (UTC by default), shown on screen. The bot reads the member count
  once a day for each chat that had activity yesterday or today, so the chart
  starts on the day the feature was deployed and has no point for a day the chat
  was quiet.
- **Top members** (admins only) ranks the users who sent the most messages in
  the window, named like the timeline. Channel posts and anonymous admins are
  not counted, and per-user counts are kept for 90 days.
- **Settings** groups each module's options under the name the commands use,
  with switches for on/off values and the default shown (with a reset link)
  once a value differs from it. Changes are saved together from a bar that
  appears at the bottom; leaving the screen or closing the panel with unsaved
  changes asks first (closing asks only on clients with Bot API 6.2 or later).
  Antiflood offers `ban`, `kick`, `mute`, `tban` and `tmute`. For `tban` or
  `tmute`, set **Flood temp-ban/mute length** in seconds (60 to 31,622,400,
  or 1 minute to 366 days). A usable saved duration can be reused when switching
  between temporary actions. Changing to an untimed action clears the duration;
  changing only the duration while the action is untimed is refused. The API
  exposes this value as `antiflood.action_time`, defaulting to `0` (unset), and
  saves the action and duration together. Invalid settings reject the whole
  batch before any values are written.
- **Filters**, **Notes** and **Blacklists** search as you type, and admins
  can delete entries or bulk-import them from a folded import box that
  reports each line's result. Read-only viewers do not see the import box.
- **Warnings** and **Timeline** (admins only) name warned users, issuers,
  actors and targets the same way; a user the bot never stored, or whose name
  it cannot read, is shown by ID.
- Only **members** of a group can open it. **Non-admin members** see the chat
  read-only; anyone else is refused (`403 not_member`), and private chats and
  channels are not served. **When the bot is not an admin** in the chat, values
  are still shown but every change is refused, because the bot could not carry
  it out.
- A user with no groups sees an empty state explaining how to add the bot or how
  to `/connect` a group.

### Warning settings

The **Warnings** group in **Settings** configures what happens when a member
reaches the warning limit; the separate **Warnings** screen lists their warnings.

| Setting | Default | Accepted values |
|---------|---------|-----------------|
| `warns.limit` | `3` | `1`–`100` warnings. |
| `warns.mode` | `mute` | `ban`, `kick`, `mute`, `tban` (temporary ban), or `tmute` (temporary mute). |
| `warns.action_time` | `0` (unset) | Punishment duration in seconds, `60`–`31622400` (366 days), for `tban` or `tmute`. |
| `warns.expiry` | `0` (never) | How long a warning counts, in seconds: `0` to disable expiry, or `60`–`31622400` (366 days). |

Choosing `tban` or `tmute` requires a usable duration in the same save or one
already stored. Switching between timed modes keeps that duration; choosing
`ban`, `kick`, or `mute` clears it. A duration cannot be saved on its own while
the mode is untimed: save the timed mode and duration together. An invalid
setting prevents the entire batch from being saved, including changes to other
modules. Opening Settings does not create a warning settings row.

### Weekly digest settings

The **Weekly digest** group in **Settings** controls the chat's weekly activity
summary. It is off until an admin enables it.

| Setting | Default | Accepted values |
|---------|---------|-----------------|
| `digest.enabled` | `false` | On or off for this chat. |
| `digest.destination` | **Default** (`""`) | **Default** (`""`), **Log channel** (`log`), or **Group** (`group`). |

**Default** sends to the chat's log channel when one is bound, otherwise to the
group. Resetting the destination saves an empty string, not the word `default`.
**Log channel** is refused while the chat has no log channel, as `/digest log` is.
Opening Settings only reads the digest choice; it does not create a settings row.

The operator's `ENABLE_DIGEST` kill switch defaults to `true`. With
`ENABLE_DIGEST=false`, no digests are sent and the panel refuses to enable them
with “The digest is disabled by the bot operator.” Admins can still view the
stored choice, turn it off, or change its destination.

### Report settings

The **Reports** group in **Settings** controls member reporting and its optional
automatic mute.

| Setting | Default | Accepted values |
|---------|---------|-----------------|
| `reports.enabled` | `true` | On or off for this chat. |
| `reports.mute_threshold` | `0` (off) | `0` to disable auto-mute, or `2`–`20` different members with open reports against the same user. |

Multiple reports from one member count only once toward the threshold. Resetting
it to `0` turns auto-mute off without disabling reporting.

Changing `reports.enabled` requires you and the bot to be chat admins.
Changing `reports.mute_threshold`, including resetting it to `0`, additionally
requires **both you and the bot** to have Telegram's `can_restrict_members`
right. An invalid setting or missing right refuses the entire save, including
changes to other modules. Opening Settings does not create a report settings row.

### Timezone setting

The **Timezone** group in **Settings** configures the same chat timezone as
`/timezone`.

| Setting | Default | Accepted values |
|---------|---------|-----------------|
| `timezone.name` | `UTC` | An IANA timezone such as `Asia/Kolkata` or `America/New_York`, or `UTC`. |

Names are saved with their canonical spelling: `asia/kolkata` becomes
`Asia/Kolkata`. Empty names, unknown zones, numeric offsets such as `+05:30`,
and the server-local name `Local` are refused. Reset saves `UTC`.

Changing or resetting the timezone requires you and the bot to be chat admins,
and you must have Telegram's `can_change_info` right. An invalid value or missing
right refuses the entire save, including changes to other modules. Opening
Settings does not create a timezone row.

The **Activity** heatmap uses this timezone. **Top members** and the **weekly
digest** keep their UTC-based windows; changing the timezone does not shift them.

### Night mode settings

The **Night mode** group in **Settings** applies selected message locks during a
daily window in the chat's **Timezone** (`UTC` by default), just like
`/nightmode`. It is off until an admin enables it.

| Setting | Default | Accepted values |
|---------|---------|-----------------|
| `nightmode.enabled` | `false` | On or off for this chat. |
| `nightmode.start` | `00:00` | A 24-hour `HH:MM` time from `00:00` to `23:59`. |
| `nightmode.end` | `00:00` | A different 24-hour `HH:MM` time from `00:00` to `23:59`. |
| `nightmode.lock_types` | `""` | Comma-separated `/locktypes` names, such as `media,url`, or `all`; `bots` is excluded. |

The start is inclusive and the end exclusive. An end before the start crosses
midnight: `23:00`–`07:00` runs overnight. Start and end cannot be equal, and
enabling requires at least one supported lock type. Types are case-insensitive;
spaces and duplicates are removed, and names are saved in sorted order.

To configure a chat while night mode is off, switch it on and save the window
and types in the same batch. Saving configuration edits while it remains off
is refused, even if you briefly switch it on and back off before saving.
Turning it off by itself preserves the stored window and types, so turning it
back on can reuse them. Locks configured with `/lock` are not changed.

You and the bot must be chat admins to save these settings. An invalid time,
unsupported type, empty type list when enabling, or refused off-state edit
blocks the entire save, including changes to other modules. Opening Settings
does not create a night mode settings row.

## Failure modes

| Symptom | Cause | Fix |
|---------|-------|-----|
| `/panel` returns 404 | The panel is disabled, or no proxy forwards the path | Set `PANEL_ENABLED=true` and forward `/panel`; the bot logs `Admin panel enabled at …` on startup. |
| No dashboard buttons in group `/settings` or `/help` | Same as above: a disabled panel adds no buttons and does not change the menu button | Enable the panel. |
| The button opens a blank page or Telegram says the app is unavailable | `PANEL_PUBLIC_URL` is not HTTPS, is missing the `/panel` path, or the BotFather Mini App points elsewhere | Use the public HTTPS panel URL in `PANEL_PUBLIC_URL` and in the BotFather Mini App. |
| The panel loads but the chat is missing or empty | The bot is not in the chat, or you are no longer an admin there | Add the bot, or reopen the panel from the group. |
| Values show but every change is refused | The bot is not an admin in that chat | Promote the bot with the rights it asks for in the add-to-group link. |
| The menu button still opens the command list | Telegram refused `setChatMenuButton`; startup logs a warning and carries on | Check the bot token and the URL; the group buttons and the `/start panel_` link still work. |
| The menu button still opens the panel after `PANEL_ENABLED=false` | The default menu button is bot-wide state, and the bot only writes it while the panel is enabled | Reset it with `/setmenubutton` in BotFather, or re-enable the panel. |
| You have no certificate yet | A Mini App cannot run over plain HTTP | Keep the panel disabled; everything else works without it. |

## Manual smoke checklist

Run this once after enabling the panel on a deployment (the Telegram items need
a real client and cannot run in CI):

1. Open `PANEL_PUBLIC_URL` in a browser outside Telegram: the shell renders and
   reports the missing `initData` instead of crashing.
2. Open it from a group's dashboard button inside Telegram: that chat opens
   directly, and Telegram's own Back button in the header leads to the chat
   list (a client older than Bot API 6.1 shows an in-page `‹ All chats` link
   instead).
3. Switch the Telegram theme between light and dark while the panel is open:
   backgrounds, cards and text follow the `--tg-theme-*` colours, and the
   Telegram header matches the page background.
4. Open it for a user with no groups: the empty state explains how to add the
   bot, with no browser console error.
5. Throttle the network to slow 3G and reload: the loading state appears first,
   then the list, with no layout shift or blank screen.
6. Open it for a user with many groups (the list is capped at 50): the list
   scrolls smoothly and every title is selectable.
7. Open the same URL inside `web.telegram.org`: the Mini App loads in the iframe
   with no `frame-ancestors` violation in the console, and the same URL also
   works standalone in the mobile Telegram app.
8. In a group, `/settings` shows two buttons and the panel button opens the
   panel for that group; with `PANEL_ENABLED=false` the second row is gone.
9. Open **Warnings**: a warning older than the chat's warn expiry is labelled
   expired, and **Remove newest warning** asks first, then deletes one entry
   (Cancel leaves it). Deleting a filter, note or blacklisted word asks the
   same way. Open **Timeline**
   with more than 50 events and scroll: the next page appends without the list
   jumping, and the action/actor filters return only matching rows.
